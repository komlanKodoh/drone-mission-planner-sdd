# Project 2 Test Plan

All cases use synthetic P1/M1/A1 data, an injected clock, and local records/aircraft fixtures. The test IDs are unique. Every rejection case asserts its stated error, no new mission/revision/selection/reservation/command was created, and the previous valid state remains. Each rejection has a same-shape valid control immediately after it. All numeric thresholds are fixture values only; no operational limit is inferred.

- **Boundaries:** AT-01/02/03/06/07/08 cover configured capacity, coordinate, time, freshness, deviation, and acknowledgement boundaries; the spec does not define a universal numeric aircraft limit.
- **Time:** UTC offsets compare as instants; test equivalent instants with different offsets and reject timestamps lacking offsets.
- **Identity/state:** wrong operator, mission, aircraft, revision, command, and status are rejected without state creation; exercise every lifecycle transition and disallowed transition.
- **Concurrency:** race two start requests against one aircraft (AT-05); exactly one atomic reservation.
- **Input types/errors/precedence:** missing, malformed, nonnumeric, NaN, and infinite fields; return field-specific errors and all independent validation blockers without sending commands.
- **Listing/returned values:** recommendation source dates, complete blocker lists, telemetry age, command history, and all saved mission-record event IDs are asserted.

## Spec gaps (reported, not resolved)

- FRs do not fully define REST request/response schemas, HTTP error codes, IDs, or the identity/authentication mechanism; contract examples provide a proposed interface.
- Several limits and policies are deliberately inputs: aircraft limits/tasks/actions, data freshness/coverage, reserve, stale/lost-link/acknowledgement/deviation thresholds. Boundary tests use explicit fixtures and do not assign real-world values.
- AC-005 does not completely specify every upload/start acknowledgement ordering, and AC-003 does not define inclusivity at evidence expiry. Tests use the conservative rule (expired is blocked) until clarified.
- The criteria do not define a missing-versus-malformed input precedence rule, persistence failure response, or all command error codes. Those are extra probes, not silently added requirements.
- Requirements FR-001–FR-011 each map to an acceptance script; NFR-001–NFR-007 do not each have a separate AC, so offline determinism, restart recovery, transaction interruption, and one-second UI timing remain unproven by this skeleton.
